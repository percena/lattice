## Acceptance (this slice)

- [x] **A2** Documented refresh path in `docs/getting-started.md` (how to refresh the local install from the repo; `npx skills add` / plugin reinstall), including the drift-check usage and the bidirectional caveat.
- [x] **A3** Tests for the drift check: simulate a stale installed tree → drift reported with an actionable message and exit 1 (not 2); in-sync tree → exit 0. DoD: fresh test output green.

## Approach (decisions journaled)

- **Decision 1 — repo `skills/` is the truth set for "Lattice skills".** The drift check iterates the subdirs of the repo `skills/` dir and compares each against the install. Non-Lattice skills that live in the install (`bailian-cli`, `ego-browser`, …) are OUT OF SCOPE — they are not flagged as drift. *Source: ticket AC + decision-policy default heuristic "minimal public surface"; avoids false positives on co-installed third-party skills.*
- **Decision 2 — bidirectional report, never auto-clobber.** The check classifies mismatches into `skill-absent-install`, `repo-only`, `install-only`, and `differs`, and NEVER writes to the install. Refresh is operator-gated. *Source: ticket IMPORTANT NUANCE — the install may hold newer/local content a blind overwrite would destroy.*
- **Decision 3 — drift exit code is 1 (never 2).** Silent `exit 2` (the original symptom on the installed `ensure-lattice.sh`) is the precise failure mode this ticket exists to prevent. Exit 2 is reserved for misuse (bad args / missing dirs), distinct from "drift detected". *Source: ticket AC ("never silent exit 2") + ADR-007 installed-tree-scope law (referenced; not yet present on this `dev` branch — see Notes).*
- **Decision 4 — ignore generated bytecode.** `__pycache__/**` and `*.pyc` are excluded from the comparison to keep the signal clean; they are not source and are recreated on run. *Source: decision-policy default heuristic "match codebase convention".*
- **Decision 5 — bash 3.2 portable (no mapfile/readarray).** Matches the repo's own portability law (see `ratify.sh` comment: "macOS system bash is 3.2"). The installed skill dirs are symlinks (`~/.claude/skills/<name> -> ../../.agents/skills/<name>`), so the check uses `find -L` to follow the symlinked start points (BSD `find` does not follow a symlinked start dir without `-L`). *Source: decision-policy "match codebase convention".*
